# 增广带噪协变混淆矩阵：构造与实施方案

日期：2026-09-14。状态：阶段 A 已执行并验证（见 `docs/implementation_notes.md` 增广带噪内核一节与 `results/raw/augmented_noise_kernel/kernel_records.jsonl`）；阶段 B 的 COA 攻击评估与阶段 D 的 block 接入尚未开始。

## 1. Target：本轮要做什么

在本地、云端持有同一基础模型的端云协同场景中，构造一个可逆、数值稳定的增广混淆矩阵，使端侧将中间表示与辅助噪声联合编码，云端通过转换后的算子继续计算，合法端侧可恢复正确结果。安全评估以唯密文攻击（COA）为目标，不向攻击程序提供目标密钥下的明文—密文配对、秘密基或解码接口。

本轮选定的技术主线：

\[
\boxed{c_{\ell,t}=[h_{\ell,t},e_{\ell,t}]M_\ell,\quad
e_{\ell+1,t}=h_{\ell,t}C_\ell+e_{\ell,t}G_\ell+\xi_{\ell,t}.}
\]

先实现和验证「增广编码—转换线性层—合法解码」的最小闭环，再连接 Transformer 非线性检查点。保持 exact 信号计算作为主线；本轮不依赖给 RMS 或 Softmax 加噪来宣称安全。

用户的核心目标保持不变：做增广带噪混淆矩阵。矩阵生成、噪声刷新、云端可计算性和 COA 评估共同构成方案，而不是单独生成一个随机数组。

## 2. Status：哪些已经成立，哪些仍待验证

**COHERENT AFTER REFRAMING / EXTRA ASSUMPTION。**

- 下面的编码解码、线性转换和合法非线性接口具有一致的代数定义。
- 「加入辅助噪声提高指定 COA 攻击的难度」是待检验假设，不是恒等式的推论。
- 「抵挡云端观察者的全流程 COA」尚未成立。现有 Gram、转换权重和接口输出必须按实际可见范围评估。
- 本文不改变现有运行配置，不覆盖已有实验结果，也不将旧文档中的攻击恢复率作为本方案结果。

## 3. Invariant Object：始终保持的对象

保持合法解码后的信号等于同一个基础模型、同一组输入下的明文信号：

\[
\operatorname{Decode}_{M_\ell}(c_\ell)=h_\ell.
\]

实数精确算术下要求恒等；实现中使用明确的浮点误差门禁。噪声幅度、矩阵条件数和攻击效果均围绕这一对象评估，不能用破坏模型计算换取无法解释的「安全提升」。

## 4. Assumptions：场景与攻击者视图

### 4.1 端云角色

本地持有原始输入、基础模型、混淆秘密和合法编解码能力。云端持有同一基础模型对应的计算能力，执行被分配的算子；要直接处理混淆状态，须加载离线转换后的权重，而不能把 c 原样送入未转换模型。

「两端相同模型」在本方案中指同一基础 checkpoint、架构和语义。转换后的云端张量因维度增加、基变换而不再与本地权重逐项相同。本地不需要为了每次请求重复运行整个模型，明文全模型运行只用于评估基线。

端侧可以参与部分计算。这与项目答辩 PPT 第 36 页的端云切分一致，不把早期手册的「客户端只能编解码」作为本方案不可放松的限制。

### 4.2 COA 的共同约束

允许知道算法、模型架构、公开基础权重、维度和公开噪声分布。允许观察同一密钥周期内的多条目标混淆记录，并利用其频率、重复模式和统计结构。

不提供目标密钥、目标秘密噪声种子、明文—密文配对、选择明文编码接口、解码接口或内部干净张量。攻击者自行用公开模型计算候选 embedding、在自选密钥上生成辅助数据，不等于获得目标密钥下的明文配对，可以纳入实验。

攻击目标包括输入 token/序列恢复和指定敏感属性预测。长度、形状、位置、调度和时序等实际可见元数据必须列出；第一版不声称隐藏这些信息。

### 4.3 分开记录两个观察范围

| 配置 | 攻击者输入 | 结果适用范围 |
|---|---|---|
| `transcript_coa` | 传输中的混淆输入、混淆返回值、公开元数据及基础模型 | 传输记录观察者；仅在部署包确实不可访问的场景适用 |
| `cloud_coa` | 上述信息，以及云端实际持有的转换权重、配置、普通输出、缓存和可见随机状态 | 执行云端的被动观察者 |

这是尚待部署合同最终确认的两个明确配置，不能只报较弱配置后统称「云端安全」。本轮实现两个输入清单，不因用户使用「唯密文」一词便假定部署权重不可见。若目标包括诚实但好奇的云端，`cloud_coa` 是必要验收项。

服务器自行生成且能观察的随机量，不可充当对服务器保密的秘密。也不能在 Python 闭包中藏一个矩阵，就认定服务器无法读取；如需依赖指定融合操作隐藏临时值，必须单独标注这一实施假设。任意修改内核、挂任意 hook、读取寄存器或读取客户端秘密不在本原型保护范围内。

## 5. Notation：符号与布局

全部采用行向量数学布局。

| 符号 | 维度 | 含义 |
|---|---|---|
| h、e、c | d、r、n=d+r | 信号、辅助噪声、混淆状态 |
| M | n×n | 密钥周期内固定的秘密可逆基 |
| M_s、M_n | d×n、r×n | M 的前 d 行、后 r 行 |
| P | n×d | M^{-1} 的前 d 列，合法信号解码映射 |
| W、b | d_in×d_out、d_out | 明文线性权重和偏置 |
| C、G | d_in×r、r×r | 信号到噪声的耦合、噪声传播 |
| ξ | r | 独立刷新噪声 |
| κ、β | 标量 | 条件数上限、辅助噪声能量比例参数 |

第一版固定链上辅助维度 r；不同 r 的转换另行扩展。矩阵存储到 PyTorch `F.linear` 前使用 `weight_pt = weight_math.T`。

## 6. Derivation Strategy / Map：推导顺序

1. 定义可逆基，将随机性分成秘密矩阵随机性和逐记录辅助噪声。
2. 从 c=hM_s+eM_n 推出合法解码与噪声在输出坐标中的覆盖。
3. 对明文线性层和噪声递推联合增广，离线吸收基变换。
4. 显式划分非线性检查点，避免把线性恒等式推广到任意非线性。
5. 将攻击者的可见信息固定为实验输入，检验安全假设。

## 7. Main Derivation：矩阵、噪声与转换

### 7.1 两种随机性分开管理

秘密矩阵 M 决定坐标变换，在一个密钥周期内固定。噪声 e、ξ 对不同请求、样本、token 位置、层和用途分别生成。

第一版不在每个 token 上直接改成 M+ΔM_t；否则已转换的权重与当前基不匹配，需重新转换或引入额外补偿。随机矩阵本身也不能替代每次编码的新噪声。

### 7.2 矩阵构造：现有基为对照，双侧全局基为候选

现有稠密生成器使用：

\[
M_{\rm baseline}=\Pi DQ.
\]

Q 正交，D 为有界正对角矩阵。该构造数值稳定，直接保留作基线。但它的行 Gram 为 ΠD²Πᵀ，是对角结构，信号行与噪声行正交；「稠密」并没有消除所有几何结构。

本轮新增一个小张量候选，避免先引入复杂多级变换：

\[
\boxed{M_{\rm candidate}=Q_L DQ_R,\qquad Q_LQ_L^T=Q_RQ_R^T=I.}
\]

用两次独立 FP64 QR 生成 Q_L、Q_R；独立采样

\[
D_{ii}=\exp(u_i),\qquad
u_i\sim\operatorname{Uniform}[-\tfrac12\log\kappa,\tfrac12\log\kappa].
\]

**恒等式：**左右正交变换不改变奇异值，所以

\[
\kappa_2(M)=\frac{\max_i D_{ii}}{\min_i D_{ii}}\le\kappa,
\qquad M^{-1}=Q_R^TD^{-1}Q_L^T.
\]

转换期计算并检验逆矩阵；部署 dtype 转换后再次检验实际条件数和 round-trip，forward 禁止求逆。

候选的行 Gram 为 Q_LD²Q_Lᵀ，一般具有非零信号—噪声交叉块。这改变了基线的特定结构，**不构成安全证明**。κ=1 时 D=I，候选退化为正交矩阵，仍有范数不变量。

初始使用 d=64、r=16、κ=3；κ=10 作为可配置硬上限，随后比较 1、3、10。全局稠密候选先限于小张量和小 block，不直接用于大模型正式性能结论。

### 7.3 增广编码和合法解码

按行分块：

\[
M=\begin{bmatrix}M_s\\M_n\end{bmatrix},\qquad
c=hM_s+eM_n.
\]

**恒等式：**设 P=M^{-1}[:,0:d]，则 M_sP=I、M_nP=0，因此

\[
\boxed{cP=h.}
\]

这证明合法方可以消去辅助噪声，不证明不知道 P 的攻击者可以或不可以恢复 h。

对同一个 h、两次独立噪声，c¹−c²=(e¹−e²)M_n。合法信号不变而观测表示变化。变化非零只是随机化检查，不能作为隐私验收。

### 7.4 独立、逐位置、可复现的噪声

第一版默认 C=0，先明确独立随机量的贡献，避免把 hC 的信号线性像误记成独立噪声。保留非零 C 接口，后续只做对照。

取 G=γP_e，P_e 为固定的 signed permutation，0<γ<1，起步 γ=0.5：

\[
e_{\ell+1,t}=\gamma e_{\ell,t}P_e+\xi_{\ell,t}.
\]

用公开校准集的隐藏向量 RMS 能量 H_ell=√E||h_ell||² 确定固定尺度，设 σ_e=βH_ell/√r。不要按每条秘密输入的范数公开调整噪声幅度。

一个便于实现的有界参考分布是独立分量均匀分布：

\[
e_{0,t,j}\sim U[-\sqrt3\sigma_e,\sqrt3\sigma_e],\quad
\xi_{\ell,t,j}\sim U[-\sqrt3\sigma_e\sqrt{1-\gamma^2},\sqrt3\sigma_e\sqrt{1-\gamma^2}].
\]

**条件命题：**对不含 attention、残差相加、裁剪和尺度切换的固定维度线性噪声链，若 Cov(e_0)=σ_e²I 且刷新独立，则 Cov(e_ell)=σ_e²I。由 Cov(e_next)=γ²σ_e²I+(1−γ²)σ_e²I 得到。此式不能直接作为完整 Transformer 噪声平稳性的证明。

β 起步 1，初筛 0、0.1、1、3；β=0 是无噪对照。逐检查点记录实际 ||e||/||h|| 的分位数、最大值和数值误差。公开尺度对应的期望比例不保证每个 token 的实际比例。若超过已验证数值预算，记录失败或在合法辅助支路内裁剪并重新混合，不能裁剪 c 后声称信号仍精确。

域分离标识采用 `(key_epoch, request_nonce, sample_id, absolute_token_position, layer_id, operation, head_id)`。位置一致保证 prefill/decode 一致；不同样本不因 batch 排列而共用随机流。重试同一逻辑记录可复用相同索引，不同记录不能复用。

数学测试可继续用现有种子工具。安全运行需单独管理高熵密钥和合适的密码学随机源；当前 PyTorch RNG、公开 runtime seed 和哈希到短整数的工具只能称可复现实验随机性。攻击进程不得读取私有复现种子，评分方可以保存；公开发布种子后的结果应标为离线评估，不能把它当作部署秘密。换 RNG 不会自动解决几何或参数泄漏。

### 7.5 线性层与仿射刷新

对 y=hW+b 和 e'=hC+eG+ξ，定义

\[
K=\begin{bmatrix}W&C\\0&G\end{bmatrix},\qquad
\widetilde W=M_{\rm in}^{-1}KM_{\rm out}.
\]

fixed_debug 将 [b,ξ]M_out 存入转换偏置，只用于正确性测试。

per_request 模式将静态偏置与刷新分开：

\[
\widetilde b_0=[b,0]M_{\rm out},\quad
c'=c\widetilde W+\widetilde b_0+\xi M_{{\rm out},n}.
\]

**恒等式：**代入 c=[h,e]M_in，可得

\[
c'=[hW+b,\ hC+eG+\xi]M_{\rm out}.
\]

运行成本包含一次增广线性运算、刷新采样和噪声映射，不能只统计 GEMM 数量。若云端直接保存 M_out,n 或其他等价注入映射，该矩阵应进入 `cloud_coa` 输入，而不能因其名称是「噪声参数」就排除。

### 7.6 噪声覆盖与低秩边界

若 Cov(e)=σ_e²I，则

\[
\operatorname{Cov}(c\mid h,M)=\sigma_e^2M_n^TM_n,
\quad \operatorname{rank}(M_n^TM_n)=r.
\]

第 j 个混淆坐标的条件噪声方差是 σ_e²||M_n[:,j]||²。生成器要记录最小值、最大值、近零坐标比例和有效秩，避免「加了 r 维噪声」实际只影响少数坐标。

现有单层块正交结构在没有辅助坐标落入的块上没有噪声贡献。应先测噪声覆盖，再决定是否使用此结构优化；双侧稠密基通常扩大坐标覆盖，但仍只有 r 维随机自由度。低秩子空间估计、重复样本差分和跨请求统计必须列为攻击，而不是通过扩大矩阵看起来的密度忽略它们。

若攻击者可见 M_n，可计算其零空间，把 e 的贡献投影掉。剩下的是信号的线性表示，未必直接等于 h，但足以否定「噪声无法消除」这一主张。应进一步测公开模型匹配和表示恢复。

## 8. 非线性接入与端云协议

### 8.1 第一个可交付闭环

1. 本地从自身基础模型取得 h，逐 token 生成 e，输出 c；第一版使用本地 embedding 或现有切分点产生 h。
2. 云端加载对应的转换线性层，计算 c'。
3. 本地用受授权的协议解码器恢复 y。调试 decode API 继续仅供测试，不能直接改名后用于云端生产 API。
4. 独立评分方比较 y 与 hW+b；攻击进程只接收对应 COA 视图。

本地 embedding 编码是一个明确的候选协议变化：上传浮点状态而非固定置换 token ID，避免把固定 token ID 和固定噪声 embedding 表误认为每次随机编码。现有 token-ID 云端 lookup 路径作为对照保留，通信增长必须计入成本。后续生成的输入/输出也要采用一致的协议，不能在首轮隐藏 token 后又在 decode 请求中发送原 token。

### 8.2 Transformer 接入原则

| 操作 | 计算约束 |
|---|---|
| RMSNorm | 对合法信号表示做 FP32 统计，gamma 吸收进后续权重；e 不能直接进入信号 RMS |
| RoPE/QK | 先 RoPE 后共同正交变换，保持正确 GQA 对应；不把 dense M 当作 RoPE 的可交换矩阵 |
| Attention Value | 保持 c_V=[V,e_V]M_V，则 Ac_V=[AV,Ae_V]M_V |
| Softmax | 第一版 exact，无 logit 噪声；无效位置保持 −∞，生产 API 不返回概率 |
| SwiGLU | gate/up 共用神经元置换，up 的有界缩放由 down 补偿；旧噪声走旁路后刷新 |
| Residual | 两支必须同 basis、同维度；噪声相加后的能量重新检查 |
| Cache | 标明层、基、密钥周期和位置；换基时重建或合法重编码 cache，不混用旧 cache |

一般 dense 增广矩阵不与上述非线性直接交换。最小闭环通过后，先用参考检查点验证一个 block 的代数；参考检查点可能持有解码能力，因此该运行仅能证明正确性，不能作为 `cloud_coa` 安全样本。

全流程 COA 评估必须选择实际可部署的检查点：复用现有云端接口，完整暴露其实际部署参数；或者利用端侧已有模型，把必要检查点放在本地。两者的通信、端侧算量不同，不能在报告中混成同一方案。端侧检查点是本构造接入方式的候选，不代表首版已决定搬回整个 attention，也不保证自动抵挡 COA。

### 8.3 当前绕过必须保留为测试

当云端拥有 P 的 Gram 矩阵 A=PPᵀ 时，cAcᵀ=||h||²。矩阵从块对角变成稠密不会消除这条恒等式；只给使用中的 ρ 加噪也不阻止离线重算。

从 Q 反推尺度的实验需使用真实 bias、RoPE、后旋转、dtype 和零坐标处理，不能只复用无偏置示意公式。部署权重能否和公开基座对齐，同样属于 `cloud_coa` 的被动分析范围。

这些测试若成功，应报告本配置失败；不能偷偷移除 A 或权重来让攻击下降。若部署合同真的排除某项，只能对应报告 `transcript_coa` 等较窄结果。

## 10. 执行顺序与验收

### 阶段 A：矩阵和线性闭环

实现两个 dense 矩阵族、逐记录噪声、线性转换和合法端侧解码。先做 d=64、r=16，随后覆盖 r=8、非方阵输出和不同输入输出基。

必须检查：条件数、实际存储精度的逆残差、M_nP≈0、完整输出 [y,e'] 的恒等式、固定种子复现、不同记录不共用噪声、相同绝对位置的 prefill/decode 一致性。FP32 小测试 ChainLinear 最大绝对信号误差 ≤1e-5；同时记录相对 L2、NaN/Inf 和实际噪声范数。固定输入重复编码变化不作为安全验收。

### 阶段 B：三个最小验证组

1. **噪声贡献：**固定矩阵族，比较 β=0、0.1、1、3，r=8、16；排除「只因加了维度或改变攻击视图」而改善的情况。
2. **矩阵贡献：**固定 r、噪声和观测预算，比较现有单侧 dense、双侧 dense、当前块结构；记录 κ、噪声覆盖、信号—噪声行交叉 Gram 和同一组攻击结果。
3. **部署贡献：**对进入 block 的候选，分别评估 transcript 与完整云端视图，核对 Gram、投影权重、噪声注入映射、Q/K 和缓存能否绕过保护。

先用小样本筛掉数值失败或被直接绕过的配置，再扩展正式规模。无需一开始对全部参数做笛卡尔积。

### 阶段 C：COA 攻击与证据隔离

攻击至少包括：密文频率/重复模式、范数/距离指纹、PCA 或子空间去噪、无标签跨记录匹配，以及在 cloud 视图下的 Gram 重算和公开权重对齐。若声称通过学习攻击也难恢复，要允许其在其他密钥/公开语料上训练，不能只测试一份不适配新矩阵的旧攻击器。

重复输入由独立评估方安排，用于模拟用户重复请求；攻击者不能选择目标编码内容、也不能获得分组真值。可另设「已知重复分组」压力测试，但需明确额外信息，不能混入纯 COA 主结果。

调参用独立公开校准数据或自选密钥。最终测试密钥、随机流和目标标签对攻击程序隔离；不通过评分接口逐次泄露标签来优化攻击。输入特征检查之外，还应检查文件路径、日志、模型对象和进程中没有秘密旁路。

记录 top-1、top-5、序列精确恢复率、敏感属性指标、候选集覆盖率与唯一匹配率。唯一候选比例为零不等于 top-1 恢复率为零。比较随机/词频基线、未混淆表示、无噪混淆和完整候选；按独立序列或请求估计区间，不把强相关 token 当独立样本。

至少比较 3 个测试密钥周期，以及同钥 100、1,000、10,000 条被动记录的观察预算；大预算可在小张量上先执行。固定密钥多记录是必要测试，不能通过每条样本换密钥逃避统计攻击。若使用轮换，报告同钥记录上限、转换/传输/缓存重建成本。

每个配置都写入 success、failure 或 skipped 记录。包含矩阵族、r、实际 κ、噪声分布、种子管理方式、公开模型来源/哈希、数据来源/样本数、攻击输入清单、攻击预算、代码版本、dtype/device 和数值结果；私有种子单独存放，不放进攻击输入或可见日志。

安全接受阈值应在最终测试前根据受保护信息的敏感程度确定。没有业务阈值时只报告相对基线的变化和未通过攻击，不能自行把某个恢复率命名为「安全」。未完成攻击训练或校准不能算防御成功。

### 阶段 D：一个 block、tiny LM、真实模型

阶段 A 通过后才能接入一个 exact block，再接 tiny 多层模型。逐层比较 RMS、QK、Value 信号、SwiGLU、残差和生成；cache、mask、GQA、ties 必须覆盖。任何 greedy 差异先排查，不能直接归因于无害浮点误差。

随机模型只用于正确性。正式任务精度使用本地真实小 checkpoint 和同一份合法可用评估集，记录 NLL/PPL、next-token top-1/top-5、生成一致性等。资源和模型/数据可用性在运行前重新审计；不下载大文件，不静默切换设备。

只有候选在相应 COA 视图下表现值得继续，才优化结构化矩阵或融合内核。当前块对角 Gram 优化不能直接等价移植到双侧基。

### 阶段 E：端云成本

以相同切分、相同输入长度、相同硬件下的无保护推理为开销基线。分别记录转换时间、端侧编解码、上传/下载字节、网络 RTT、云端 prefill/decode、峰值内存和 KV cache。

一个方阵线性层从 d×d 增广到 (d+r)×(d+r)，理论乘加数量比例为 (1+r/d)²；这不包括矩阵编码、刷新、非线性、网络和调度，不能当作端到端延迟。

项目 PPT 的安全成本指标是 ≤10%/token，国产适配吞吐率损失是另一项 <5% 指标。定义主预算为 Δcost/cost_baseline，并另列 Δcost/cost_protected 以对应「整体成本」可能的分母歧义；成本单位和计算/通信权重须预先固定，未确定时分项报告，不将毫秒和字节直接相加。

## 11. Remarks and Interpretation：为什么先这样做

第一版真正增加的是可控、独立、逐记录变化的辅助随机性，以及一个可与当前结构公平比较的全局混合基。C=0 帮助分离随机遮蔽与信号复制；双侧基帮助检验特定行正交/局部块结构是否造成容易利用的不变量。两者都保留合法方的线性精确恢复。

这是一条可实施、可失败、可归因的路线。若双侧基没有提高攻击难度，就保留更便宜的基；若只改善 transcript 而 cloud 仍被绕过，就明确限制成果范围，并利用已有端云切分重新设计暴露边界。不能将换矩阵族直接写成已解决 Gram 泄漏。

## 12. Boundaries and Non-Claims

- 可逆性、低条件数、密文改变、矩阵元素非零、测试通过都不等于 COA 安全。
- bounded 辅助噪声不自动提供差分隐私；实数增广状态不是标准 LWE 密文。
- 改成双侧基不会自动消除公开转换权重泄漏，也不隐藏全部几何结构。
- fixed_debug、固定噪声表和公开可复现种子不作为部署保密机制。
- 一种攻击变弱不证明所有唯密文攻击失效，不承诺输入机密性或端到端加密。
- 一般服务器可修改内核、导出寄存器或读取客户端秘密时，本原型单独不能保护干净中间量。
- 本轮不提出已验证的最佳参数、不引用缺 raw 的 τ-sweep 数字、不宣称已满足项目开销目标。

## 13. Open Risks：实施中优先排除的风险

1. **低秩随机性：**全局覆盖仍只有 r 维噪声；重复记录可能暴露噪声子空间。
2. **参数可见性：**注入映射、Gram、转换投影可能使 cloud 观察者绕过噪声。
3. **固定 ID 通道：**保留云端 token lookup 时，频率与重复信息不会因隐藏向量加噪而消失。
4. **随机流范围：**广播噪声、重复 nonce、公开 seed 可能抵消逐记录随机化的意义。
5. **数值与性能：**dense 基导致 dense Gram 或额外信号提取；不能承诺当前块结构的低开销。
6. **协议切换：**本地编码上传状态的带宽与往返成本可能超过目标，需与云端 lookup 基线分开测量。
