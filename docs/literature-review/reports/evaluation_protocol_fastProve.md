## 1. 为什么通用评测骨架不能直接照搬

文献调研文档（`plaintext_vs_obfuscated_accuracy_survey.md`）第 8 节提出的 Q/C/Δ 框架、明文—降精度—混淆对照、相同输入对齐、置信区间与消融实验**方向正确**，但它是为通用 HE/MPC/TEE 推理设计的。fastProve 的架构是：

* **增广状态**：(z_ℓ = [h_ℓ, e_ℓ])，其中 (h_ℓ) 是真实信号，(e_ℓ) 是辅助噪声状态，(r_ℓ ≪ d_ℓ)；
* **可逆基混合**：(c_ℓ = z_ℓ M_ℓ)，(M_ℓ) 可逆；
* **链式噪声**：噪声通过 (e_0, C_ℓ, ξ_ℓ) 等注入，设计上要求**噪声与真实信号正交传播**；
* **非线性检查点**：Q/K 正交变换、混合 Value、fused attention、MoE 路由等。

这套架构的**数学主张**是：真实信号计算不受噪声链影响；Attention 中 QK score 和 Softmax 概率应保持一致；Value 噪声不影响真实 AV；MoE Top-k 集合应保持一致；最终输出只发生词表置换。

因此，评测方案**必须从普通的「任务准确率比较」升级为五层体系**：

```
代数等价性
  → 有限精度误差
    → Softmax/Top-k 离散一致性
      → 输出分布一致性
        → 下游任务精度
```

否则，即便最终 MMLU 只下降了 0.2%，也**无法判断**这 0.2% 究竟是正常 BF16 舍入、增广矩阵病态、Softmax 排序翻转，还是 MoE 路由发生了错误——因为内部错误可能在平均任务分数中相互抵消。

## 2. 当前方案中最关键的四个问题

### 问题 1：B2 不应该直接与 B0 比

调研文档的基线定义：

| 条件 | 定义 |
|---|---|
| B0 | 明文 FP32 |
| B1 | 明文低精度 |
| B2 | 混淆 exact mode，noise=0 |
| B3 | 混淆 nominal noise |

其中「B2 应该 match B0」的主张**存在混杂因素**：若 B0 是 FP32 而 B2 运行在 BF16 上，则 B2−B0 **同时包含了精度误差和混淆误差**。

**正确比较**：B2 应与**同精度的 B1** 比，而不是直接与 B0 比。

### 问题 2：「noise=0」模式必须保留完整混淆计算图

B2 不能简化为一个接近明文模型的版本。它**必须保留**：

* 增广维度 (D+R)；
* 相同的混合矩阵与变换后权重；
* 相同的 Q/K 正交变换；
* 相同的混合 Value 布局；
* 相同的 fused attention；
* 相同的 KV Cache 格式；
* 相同的 FFN 置换与缩放；
* 相同的 LM Head 词表置换。

**只把** (e_0, C_ℓ, ξ_ℓ) 或等价的噪声注入项设为零。

否则，B2 与 B3 的计算图都不相同，测出的差值**不能被解释成「噪声导致的精度损失」**。

**建议重命名**：B2 改为 **「结构混淆模式 / structural-only mode」**，而不是含义模糊的 exact mode。

### 问题 3：任务准确率只是最后一层指标

不能只测：MMLU、C-Eval、Perplexity、ROUGE、最终 token exact match。

因为下列情况可能**同时发生**：某些 Attention 行已经发生排序翻转、某些 prompt 输出变差、另一些 prompt 恰好变好、最后平均准确率看起来几乎没变。**平均任务分数可能把内部错误抵消掉**。

### 问题 4：我们的目标不应照搬 AloePri 的「低于 3% 损失」

AloePri 自身包含近似性的 Attention block permutation、RMSNorm 近似补偿和高维矩阵数值效应，因此它报告「多数任务损失低于 3%」是符合其方案性质的。

但 fastProve 当前方案声称的是：**噪声与真实信号正交传播，真实信号计算保持不变**。所以理论目标不是「接受 3% 的损失」，而应该是：

> **精确算术下零算法损失，有限精度下仅有可解释的数值误差。**

AloePri 的实验反而给了我们一个重要警告：它在较大的 key-matrix 系数下，FP32 仍稳定，而 BF16 准确率发生严重崩塌；论文将其归因于内部状态范数范围变大并导致溢出风险。

因此我们必须把以下指标加入消融：

```
|M_ℓ|，|M_ℓ^{-1}|，κ(M_ℓ)，|c_ℓ|，|e_ℓ|
```

不能只消融「噪声大小」。

## 3. 新版条件矩阵：精度 × 模式二维设计

比原来的 B0–B3 更严谨的方式，是使用**「精度 × 模式」二维矩阵**。

### 3.1 条件定义

| ID | 数值精度 | 模式 | 作用 |
|---|---|---|---|
| **F0** | FP32 | 明文 | 高精度参考 |
| **F1** | FP32 | 结构混淆、无噪声 | 验证基变换和增广实现 |
| **F2** | FP32 | 完整链式噪声 | 验证噪声是否真正与信号解耦 |
| **P0** | BF16 | 明文、生产 kernel | 真实生产基线 |
| **P1** | BF16 | 结构混淆、无噪声 | 测量变换造成的数值放大 |
| **P2** | BF16 | 完整方案、标称参数 | **最主要结果** |
| **P3** | BF16 | 完整方案、压力参数 | 定位数值稳定边界 |

### 3.2 报告退化量

**FP32 下的分解**：

* (Δ\_{struct}^{FP32} = Q(F0) − Q(F1))：基变换和增广造成的损失；
* (Δ\_{noise}^{FP32} = Q(F1) − Q(F2))：噪声链造成的损失。

**BF16 下的分解**：

* (Δ\_{struct}^{BF16} = Q(P0) − Q(P1))：结构混淆在有限精度下的数值放大；
* (Δ\_{noise}^{BF16} = Q(P1) − Q(P2))：噪声链在有限精度下的损失。

**最终用户关心的量**：

> **Δ\_{prod} = Q(P0) − Q(P2)**

即：在**相同硬件、相同精度、相同推理框架**下，完整混淆模型相对明文模型损失多少。

### 3.3 指标方向约定

对于 PPL、NLL 等「越小越好」的指标，定义**相对增量**：

```
Δ_PPL^rel = PPL_obf / PPL_plain − 1
```

对于 Accuracy 等「越大越好」的指标，定义**百分点差**：

```
Δ_Acc^pp = Acc_plain − Acc_obf
```

**必须明确区分**：

* 百分点（percentage point）：例如 80% → 78% 为 **2 pp**；
* 相对百分比（relative percent）：同样情况为 **2.5%**。

## 4. 五层精度评估体系

这是本方案的核心交付。对每一层，都给出**必测内容、具体指标、建议门槛**。

---

### 第 1 层：逐算子数值等价性

在调试模式中，对混合状态进行合法解码：

```
ĥ_ℓ = Decode_ℓ(c_ℓ)
```

然后比较：

* (E_{ℓ,∞} = |ĥ_ℓ − h_ℓ|_∞)：最大绝对误差；
* (E_{ℓ,rel} = |ĥ_ℓ − h_ℓ|₂ / (|h_ℓ|₂ + ε))：相对误差。

**必测模块**：

| 模块 | 必测内容 |
|---|---|
| Embedding | 解码后的 embedding 误差 |
| ChainLinear | 信号输出误差与噪声正交残差 |
| RMSNorm | RMS 标量、方向和输出误差 |
| Q/K | 变换后点积误差 |
| Value | 解码后真实 Value 误差 |
| Attention Output | AV 信号误差 |
| SwiGLU | (z′ = zDΠ) 的误差 |
| Down Projection | 恢复后输出误差 |
| LM Head | 逆词表置换后的 logit 误差 |

**门槛**：FP32 单元测试上限可保留手册的 (max|ĥ − h| ≤ 10^{−4}) 作为基础门槛。

但手册中 BF16 的「相对误差不超过 5×10^{−2}」**只能作为早期 smoke test**，不能作为最终端到端验收标准——5% 的层级误差完全可能导致输出 logit 排序翻转。

---

### 第 2 层：Attention Softmax 排序与分布

这是 fastProve **最需要单列的一层**。

对每一层、每个 Head、每一个合法 Attention 行，定义：

* (ε_{l,h,i}^S = max\_{j∈V\_i} |S̃\_{l,h,i,j} − S\_{l,h,i,j}|)：Softmax score 最大绝对误差；
* (m_{l,h,i}^S = S_{(1)} − S_{(2)})：明文 score 最大值与第二大值的 margin。

**关键定理**：当 (m\_{l,h,i}^S > 2ε\_{l,h,i}^S) 时，可以保证该行的 Attention top-1 **不翻转**。

**必测指标**：

| 指标 | 含义 |
|---|---|
| Score max absolute error | QK 数值误差 |
| Score relative error | 不同层之间可比 |
| Softmax KL divergence | 整个概率分布变化 |
| Total variation distance | 概率质量变化 |
| Attention top-1 match | 最大 Attention 位置是否一致 |
| Attention top-k overlap | 前 k 个位置是否一致 |
| Rank-flip rate | 合法位置相对排序翻转比例 |
| (m ≤ 2ε) 比例 | 理论上存在翻转风险的行比例 |
| AV relative error | 最终聚合结果误差 |

**目标**：对于 fastProve 的严格 Q/K 设计，**Attention rank-flip rate = 0**，至少在发布验证集上必须为零。

**不能**只报告 Softmax 概率的平均 MSE——平均值很小也可能伴随关键位置的排序翻转。

---

### 第 3 层：MoE Router 离散一致性

如果模型包含 MoE，需要报告 TopK(r) 与 TopK(r̃) 的**逐 token 一致性**。

**必测指标**：

| 指标 | 目标 |
|---|---|
| Expert set match | 100% |
| Expert order match | 视实现是否要求顺序一致 |
| Gate-weight L1/KL | 接近 0 |
| (Δ\_k = r\_(k) − r\_(k+1)) 分布 | 描述边界稳定性 |
| (2τ < Δ\_k) 违反率 | 0 |
| 低 margin 回退率 | 单独报告 |
| 首次路由分歧层 | 用于故障定位 |

如果 Top-k 只达到 99.9%，**不能**简单说「几乎无精度损失」——一次早期专家选择错误可能影响后续全部 token。

---

### 第 4 层：输出 logit 与 token 轨迹

混淆模型的词表位置经过置换，首先需要**逆对齐**：

```
ℓ̂\_t^{obf} = ℓ̃\_t^{obf} · Π\_{voc}^T
```

然后比较：

* (ε\_t^ℓ = |ℓ̂\_t^{obf} − ℓ\_t^{plain}|_∞)：logit 最大误差；
* (D\_{KL}(p\_t^{plain} ‖ p\_t^{obf}))：输出分布 KL；
* (m\_t^ℓ = ℓ\_{t,(1)} − ℓ\_{t,(2)})：输出 logit margin。

同样，当 (m\_t^ℓ > 2ε\_t^ℓ) 时，greedy token **一定不翻转**。

**必测指标**：

| 指标 | 说明 |
|---|---|
| Logit max error | 最坏词表位置误差 |
| Logit relative (L₂) error | 整体数值误差 |
| Probability KL/JS | 输出分布变化 |
| Top-1 token agreement | 下一 token 一致率 |
| Top-5 overlap | 候选集合稳定性 |
| Margin-risk rate | (m\_t^ℓ ≤ 2ε\_t^ℓ) 比例 |
| Greedy sequence exact match | 整段生成完全一致 |
| First-divergence position | 首次分歧位置 |
| Common-prefix length | 自回归误差何时出现 |

**两类测试都必须运行**：

* **Teacher-forced 测试**：对明文与混淆模型输入完全相同的真实前缀，逐位置比较 logits。**不会**受到「前一步 token 不同导致后续上下文不同」的干扰，是最重要的数值评估。
* **Free-running 测试**：明文和混淆模型分别自回归生成，比较完整序列。反映真实用户体验，但一处微小分歧可能在后续被放大，因此定位能力较弱。

---

推荐任务（沿用 AloePri 的实验结构，可借鉴）：

## 5. 消融变量重新设计

调研文档中的「多项式阶数、固定点位宽」等更适合 HE/MPC，**不是** fastProve 的主要变量。

fastProve 应当消融：

| 变量 | 示例 |
|---|---|
| 主噪声维度 (R) | 0、8、16、32 |
| Value 噪声维度 (R_h) | 0、1、2、4 |
| FFN 噪声维度 (R\_{ff}) | 0、8、16、32 |
| 初始噪声幅度 | 0、0.5×、1×、2× |
| 刷新噪声 (ξ_ℓ) | 不同方差 |
| 衰减系数 (γ_ℓ) | 不同稳定区间 |
| 基矩阵条件数 | 按 κ(M_ℓ) 分桶 |
| 精度 | FP32、BF16、FP16 |
| 序列长度 | 128、512、2k、4k 或模型上限 |
| Attention 实现 | reference、SDPA、Flash/Fused |
| KV Cache | cache/no-cache、prefill/decode |
| 模型结构 | Dense、GQA/MQA、MoE |
| 密钥 | 多个独立混淆密钥 |

其中**最关键**的不是简单报告「噪声越大，精度越差」，而是绘制：

* 误差 vs. max\_ℓ κ(M_ℓ)；
* 误差 vs. max\_ℓ |c_ℓ|∞；
* 误差 vs. |e_ℓ| / |h_ℓ|。

理论上，真实信号和噪声正交时，精度曲线应当在较大范围内**近似平坦**；到达数值动态范围边界后，可能出现**突然崩塌**，而不是平滑下降。

## 6. 密钥与统计方法

### 6.1 「至少三个 seed」需要改成「至少三个独立密钥」

fastProve 至少存在三类随机性：

1. **混淆密钥随机性**：不同置换、基矩阵、噪声子空间；
2. **噪声随机性**：同一密钥下的不同刷新噪声；
3. **生成随机性**：temperature/top-p sampling。

**最重要的是第一类**。

建议：

* 至少 **3 个**，最好 **5 个**独立主密钥；
* 每个主密钥完整转换一次模型；
* 每个密钥运行同一测试集；
* 置信区间同时覆盖**样本差异和密钥差异**；
* sampling 实验再叠加生成随机种子。

只用同一个转换模型运行三个 sampling seed，**不能**说明方案对不同增广基和不同条件数稳定。

### 6.2 统计方法不能只报平均值

实验是天然的 **paired design**：同一条样本同时经过明文模型和混淆模型。因此应使用**配对统计**，而不是独立样本比较。

建议：

* Accuracy：paired bootstrap 或 McNemar；
* PPL/NLL：按文档或样本做 paired bootstrap；
* token agreement：Wilson 或 Clopper–Pearson 区间；
* 多密钥：分层 bootstrap，先采密钥，再采样本；
* 报告 **95% CI**，而不只是点估计；
* **预先规定 non-inferiority margin**，不能看完结果后再设门槛。

### 6.3 「100 条全部一致」不是充分证据

手册中「100 条提示全部一致」只能作为开发 smoke test。

粗略按照二项分布的 rule of three：100 条样本中零失败，其真实失败率的 95% 上界仍约为 3/100 = 3%。

所以「100/100 一致」**不能支撑「误差率为零」**。

如果希望把 token-level 分歧率约束到 10^{−4} 量级，需要数万乃至更多对齐 token 决策，并且还要考虑自回归 token 之间并非独立。

## 7. 最终验收标准

### 7.1 硬正确性门槛

这些是本方案数学主张**直接要求的**，不宜用「平均下降少于 1%」替代。

| 项目 | 建议门槛 |
|---|---|
| FP32 ChainLinear | max abs error ≤ 10^{−4} |
| Attention score ranking | **翻转率 0** |
| Attention top-1/top-k | 100% 一致 |
| MoE expert set | 100% 一致 |
| Causal mask | 100% 一致 |
| Cache vs no-cache | 输出一致 |
| LM Head 逆置换后 argmax | 100% 一致 |
| Greedy 发布验证集 | 完整序列 100% 一致 |

### 7.2 统计效用门槛

可以作为**工程非劣门槛**：

* 多选/分类准确率下降不超过 **0.5 percentage point**；
* PPL 相对增加不超过 **1%**；
* 95% CI 不越过预先规定的非劣界。

但这些**不能**被称为跨任务、跨模型的统一理论标准。CrypTFlow2（ResNet50 76.47→76.45，0.02 pp）和 Slalom（<0.5% @ 8-bit）的主要结果来自 CNN、固定点或 TEE 环境，不能简单视为 Transformer 混淆方案必须「击败的全球准确率下限」。

对于 fastProve 的严格协变方案，真正目标应当仍是：

> **Δ_prod ≈ 0**

而不是满足于低于 0.5 pp。

## 8. 对调研文档的采纳与重写清单

### 8.1 适合保留的内容（来自调研文档第 8 节）

* Q/C/Δ 总框架；
* 同一数据、同一顺序、同一生成参数；
* 明文高精度、明文生产精度、混淆模式分离；
* 精度、噪声、层选择、序列长度消融；
* 95% 置信区间；
* 任务精度、PPL 和性能联合报告。

### 8.2 需要重写的核心点

1. **B2 应与同精度 B1 比较，而不是直接与 FP32 B0 比较；**
2. **增加 FP32/BF16 × 明文/结构混淆/完整混淆的二维实验矩阵；**
3. **增加逐层、Attention 排序、MoE Top-k、logit margin 指标；**
4. **先做 teacher-forced logit 比较，再做自由生成；**
5. **使用多个独立混淆密钥，而不仅是生成随机种子；**
6. **把矩阵条件数和内部动态范围列为核心变量；**
7. **正式报告中使用「混淆态相对明文」，而不是密码学意义上的「密文相对明文」**——因为 fastProve 不是标准 LWE 密文或完全加密推理，而是**实数增广协变混淆**。（2026-08-06 更正：原文此处写作「LWE-keyed / LWE-inspired 的低开销协变混淆」，该措辞不可用——构造在实数域精确可逆，`h = c·(M⁻¹)[:, :d]` 对任意辅助态成立，不具备任何 LWE 属性。见 `docs/threat_model.md` 第 5bis 节。）

### 8.3 按照上述修改后，这套评估能真正回答

> 精度损失究竟来自普通 BF16、增广基数值条件、噪声动态范围、Softmax 排序翻转，还是方案实现错误。

也才能使最终的「0 精度损失」或「低于某个阈值」的结论**具备可审查性**。
