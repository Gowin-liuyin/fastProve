## 0. 一句话结论

**先说结论，再展开：**

> 我们的问题不在"代码写得对不对"，也不在"有没有忠实还原论文"——
> 数学核心是严格正确的（13 项恒等式 + 303 个测试全过）。
> 问题在于：**这套构造为了让模型算得对，必须把一个"指纹"（向量范数）
> 暴露给服务端，而这个指纹足以把用户的输入原文恢复出来。**
> 这是构造本身的结构性缺陷，不是 bug，工程手段修不掉。

Aloepri 上游最近的两项优化（attention 逐组采样、BlockPerm 的 γ 参数）
属于"把论文还原得更像论文"，跟这个指纹问题**完全不在同一层**，所以
解决不了我们的问题。详见 §4。

## 2. 先用大白话讲清楚我们的方案是怎么工作的

### 2.1 核心想法：换一把"坐标架"

把模型的隐藏状态 `h` 想象成空间中的一个点。明文推理时，服务端直接看到
这个点的"直角坐标"。我们的做法是：

```
c = [h, e] · M
```

- `e` 是一小段辅助噪声坐标（维度 r ≪ d）；
- `M` 是一个客户端保密的可逆矩阵。

服务端看到的是 `c`——同一个点在另一套坐标架下的读数。因为 `M` 可逆，
线性层可以整体换算：服务端拿到的部署权重是 `M⁻¹KM`，它算出来的结果
`c·(M⁻¹KM)` 恰好等于 `[明文结果, 噪声结果]·M`。**信号部分和明文一模一样**，
只是换了个坐标架存放。这就是"协变"的含义，也是 13 项恒等式验证的东西。

这套机制对**线性层**（矩阵乘法）是严格成立、无损耗的。

### 2.2 麻烦出在非线性层

Transformer 里不全是矩阵乘法。RMSNorm、Softmax、Top-k 路由这些
**非线性操作不认识"换坐标"这回事**——它们需要拿到合法表示的信号才能算。

工程上的解法是：在指定的融合内核里，把信号部分"解"出来，喂给非线性层，
再把结果混回去。这就是方案文档说的"非线性检查点"。

**到这里为止一切正常。真正的问题是下面这个。**

## 3. 核心问题：RMSNorm 必须算对 `ρ`，而 `ρ` 就是指纹

### 3.1 `ρ` 是什么，为什么躲不开

RMSNorm 的公式：

```
输出 = h / rms(h) · γ        其中 rms(h) = sqrt(‖h‖²/d + eps)
```

记 `ρ = rms(h)`。要算对 RMSNorm，就**必须**算对 `ρ`。而：

```
ρ² = ‖h‖²/d + eps   ⟹   ‖h‖² = (ρ² − eps)·d
```

也就是说：**`ρ` 在代数上就是向量 `h` 的长度（范数）。** 这不是实现上的
偶然选择，是模型语义的一部分——范数算错，模型输出就错。

### 3.2 为什么范数能还原 token（第 0 层）

第 0 层的输入 `h₀` 恰好就是 embedding 表的一行。关键性质：

> **每个 token 的 embedding 行范数几乎各不相同。**

- Qwen2-1.5B：99.05% 的行范数互不相同；
- Llama-3.2-3B：100% 互不相同。

而基座模型是公开的（DeepSeek/Llama 都开源），攻击者可以离线建一张
**"范数 → token"查找表**。于是：

```
服务端看到 ρ = 0.0336763351
    → 查表 → 唯一匹配 → "起"
服务端看到 ρ = 0.0288048360
    → 查表 → 唯一匹配 → " diabetes"
```

实测（PROBLEMS.md §1.1，n=4000）：

| 模型 | ρ 存储精度 | 唯一且正确恢复 |
|---|---|---:|
| Qwen2-1.5B | FP32 | **92.5%** |
| Llama-3.2-3B | FP32 | **93.4%** |

端到端演示直接恢复了 `"I am a patient with diabetes"` 整句。

**这个攻击有多"便宜"**：

| 攻击需要什么 | 需要？ |
|---|---|
| 已知明文对 (h, c) | ❌ |
| 知道保密矩阵 M | ❌ |
| 修改 kernel / 读寄存器 | ❌ |
| 公开 base checkpoint | ✅（而主流基座都公开） |

不需要任何特权，只需要"服务端本来就要算的量"和"公开的模型"。

### 3.3 三个常见的"辩护"为什么都不成立

**辩护一："ρ 只在融合内核寄存器里，不写显存，读不到。"**

不成立。融合 RMS-QKV 操作必须**输出 Q**（注意力要用），而服务端必然
持有混淆态 `c` 和部署权重 `W_q`。三者摆在一起：

```
Q = (c · W_q) / ρ    ⟹    ρ = (c · W_q) / Q
```

一次逐元素除法就把 `ρ` 反推出来了。**`ρ` 由必须同时存在的输入和输出
代数地确定**，不需要任何"内部读取"。（实测：Q 用 FP32 输出时，反推
`‖h‖` 相对误差仅 1.45e-08。见 PROBLEMS.md §1.2 / threat_model 5bis.10。）

**辩护二："用 BF16 存 ρ，精度低了就查不出来了。"**

部分成立但代价致命：BF16 下恢复率确实降到 0%，但 4.7e-03 的相对误差
远超 exact 门禁的 1e-3 logit 容差——**隐私失败换成了正确性失败**。
而且 §1.2 显示：即使 Q 用 BF16 输出，反推 `‖h‖` 的精度（7.9e-04）
仍好于 ρ 自己用 BF16 存储时的精度。BF16 不是解法。

**辩护三："客户端多算几层（边云切分），让 ρ₀ 不出客户端。"**

实测不能归零。残差流保留了 embedding 的贡献（`h_ℓ = h₀ + Σ更新`），
所以范数信息在**所有深度**都在。Qwen2 全 28 层实测：稀有 token 的
范数最近邻预测从第 0 层的 100% 到第 28 层仍有 49.4%（基线 8.7%）。
切到第 1 层只把 98.7% 降到 77.9%，且违反"客户端只做编解码"的设计原则。
（见 PROBLEMS.md §1.3 / threat_model 5bis.11。）

### 3.4 其他几条同源的泄漏通道（简述）

它们和 §3.2 是同一个病根的不同表现——**"非线性层需要的量本身就是敏感信息"**：

| 通道 | 一句话说明 | 详见 |
|---|---|---|
| Gram 块暴露 | 部署路径用块对角 Gram 形式算 ρ，服务端必然持有它 → `h` 的所有成对距离/内积在 FP64 舍入量级内**精确**可读 | §1.4 / 5bis.8 |
| M 可逆 ⇒ h 无损可恢复 | `c = [h,e]M` 是实数可逆变换，`h = c·(M⁻¹)[:,:d]` 精确成立；噪声放大 10¹² 倍后仍可恢复到 5.7e-04 | §1.5 / 5bis.1 |
| 噪声读出矩阵 N 在部署权重里 | 观察部署权重者可恢复辅助噪声 `e`（up to 一个可逆映射） | §1.6 |
| 辅助噪声 98% 是 h 的线性像 | `e' = hC + eG + ξ` 中 `‖hC‖ ≈ 2.94` vs `‖ξ‖ ≈ 0.056`，"噪声"主体是信号的线性函数 | §1.7 |
| QK 分数几何可见 | `common_qk` 变换在 RoPE 之后应用，无法吸收进部署权重 → 分数多集与排序结构对服务端可见 | §2.3 / 5bis.6 |

### 3.5 为什么说"不可修"：四条约束的不可能三角

把方案的目标形式化成四条：

```
C1  输出与明文模型逐位一致（误差 ≤ 门禁容差）
C2  在线开销 ≤ 5%，客户端只做编解码
C3  无可信边界（不用 TEE / MPC / HE）
C4  服务端无法恢复输入 h
```

推理链条：

```
C1 ⟹ ρ 必须算对 ⟹ ‖h‖ 泄漏        （§3.1–3.2）
C2 ⟹ Gram 块必须在服务端 ⟹ 几何精确暴露 （§3.4）
C3 ⟹ 没法把 ρ 的计算移出观察范围
三者合起来 ⟹ ¬C4
```

**每放弃一条，剩下三条可以成立。** 方案文档隐含假设四条能同时成立，
这就是层次上的遗漏：文档把注意力全放在"线性层协变性"的推导上（这部分
是对的），但漏掉了"非线性层需要的标量（rms、排序、间隔）本身就是敏感
信息，而且不能不算"。

一个直白的类比：你把一封信装进不透明的信封（混淆态 c），但邮局盖章时
**必须在信封外面写下信纸的重量**（ρ = ‖h‖）。而你知道每张信纸的重量
都不一样，且weight表是公开的（公开 embedding）。信封再不透明也没用。

## 4. 为什么上游的两项优化解决不了我们的问题

逐项对照：

| 我们的问题 | 逐 KV 组采样 | BlockPerm γ |
|---|:---:|:---:|
| §3.2 ρ 泄漏 ‖h‖ → token 恢复 92–93% | ❌ | ❌ |
| §3.3 辩护一（Q 反推 ρ） | ❌ | ❌ |
| §3.4 Gram 几何精确暴露 | ❌ | ❌ |
| §3.4 M 可逆 ⇒ h 无损可恢复 | ❌ | ❌ |
| §3.4 QK 排序结构可见 | ❌ | ❌ |
| §2.2 块对角基降低已知明文攻击代价 | ❌ | ❌ |

原因很简单：

1. **ρ 攻击不需要知道任何变换矩阵。** 不管 R/H/Z 是全体头共享还是逐组
   独立采样，不管 BlockPerm 怎么采样窗口，`ρ = rms(h)` 这个量都照样
   存在、照样必须算对、照样等于 `‖h‖`。攻击的输入是"服务端本来就要
   用的数"，与密钥材料的分布无关。
2. **逐组采样增加的是密钥多样性，不是不可逆性。** `c = [h,e]M` 的可逆
   性（§3.4 第二行）是构造的代数性质——只要 M 是实数可逆矩阵，h 就
   无损编码在 c 里。给每个头发不同的 M 不改变这一点。
3. **γ 只影响置换的采样分布。** 它甚至不在我们问题的攻击面上。

打个比方：我们的问题是"信封外面写了信纸重量"，上游的修复是
"把信封的封口花纹改成每封信不一样、并按论文补上花纹的选择概率"。
花纹再讲究，重量还印在外面。

### 4.1 一个容易被忽略的反向信号

上游自己的审计显示，其当前主路径**精度是坏的**（`strict_method_audit.md`
"验证结果"节）：

- raw-L2 κ 路径下，logits 最大绝对误差 **19.83–28.82**，relative L2
  **1.18–1.53**，最后一个 token 的 argmax 匹配 **0/4**；
- 8 题任务 smoke：明文 87.5% vs 混淆 **12.5%**；
- κ 的尺度矛盾（§5.2.5 用原始 L2 比值、§5.4 用扩维 RMS，相差
  sqrt(D/d)）他们自己标注为"未归因、未解决"。

对比：我们的 exact 门禁在 FP32 下全 PASS（`results/raw/exact_gate_D1.json`），
数学核心有 13 项独立 FP64 恒等式背书。**"看着加他们的方案"目前没有
可取的增量**——他们还在修正确性，我们已经过了正确性、在分析隐私上界。

### 4.2 但有一点值得警惕：同类构造逃不掉同样的攻击

上游的 RMSNorm 用"扩维 RMS"（D = d + 2h 维），看似和我们的块对角
Gram 不同，但 **RMS 归一化永远是范数的函数**。只要它的服务端也要算对
归一化因子，§3.2 的"范数 → token"通道原则上同样存在——只是他们还没
做这个攻击分析。这反过来印证：这不是我们实现的特有缺陷，是
**"输出精确 + 无可信边界"这类协变/混淆构造的共同结构弱点**。

## 5. 我们已经做了什么、还差什么

### 5.1 已落地的折衷

当前部署配置（`configs/tiny_approx.yaml`）：

- exact 模式（`rho_noise_bound: 0`）保留为正确性工具；
- 生产折衷：`per_request` 仿射刷新 `e' = hC + eG + ξ` **加上**有界 ρ 扰动
  （`rho_noise_bound: 1e-5`）。

实测效果（真实 Qwen2-1.5B 全 28 层，PROBLEMS.md §4.3）：

| τ | token 恢复率 | logit max err | argmax 一致 |
|---|---:|---:|---:|
| 0（exact） | 93.8% | 0 | 100% |
| 1e-6 | 49.2% | 1.1e-3 | 100% |
| **1e-5** | **3.9%** | 2.0e-3 | **100%** |
| 1e-4 | 0.2% | 2.2e-2 | 100% |

注意：τ=1e-5 时恢复率从 93.8% 砍到 3.9%，argmax 仍 100% 一致——
**但 argmax 一致 ≠ 任务精度不掉**。PPL/MMLU 在 τ=1e-5 下掉多少
**还没测**，这是当前最大的证据链缺口（§4.3 缺口）。在补测之前，
不得声称"τ=1e-5 是可用操作点"。

同时要清楚这个折衷**不关闭**的通道：Gram 几何（§3.4）、M 可逆恢复
（§3.4）、`e ≈ hC` 线性像（§3.4）。它只压制"未扰动 ρ → 行范数 → token"
这一条最便宜的攻击。

### 5.2 缓解路线全景与状态

| 路线 | 消除程度 | 代价 | 状态 |
|---|---|---|---|
| 1. ρ 加有界噪声（已落地） | 93.8% → 3.9% (τ=1e-5) | 放弃 exact 名分；任务精度未测 | ✅ 已测 |
| 2. 边云切分前 k 层 | 不能归零（49.4% 残留） | 客户端算力 + 违反设计原则 | ✅ 已测，否决 |
| 3. 范数均衡 embedding | 第 0 层完全消除 | 改 embedding + 首层；只解决第 0 层 | ❌ 未实现 |
| 4. 换代数结构 (mod-q) | 可能真正解决 | 未知；与 ≤5% 开销冲突 | ❌ 未实现 |
| 5. TEE / MPC 包住 c 流 | 完全解决 | 引入可信边界，违反 C3 | ❌ 违反约束 |

### 5.3 证据链缺口（不是错误，是没做完）

1. **所有精度结论曾跑在随机 tiny 模型上**——好消息：真实 checkpoint
   已确认在本机（Qwen2-1.5B、Llama-3.2-3B），且部分 exact 模式
   预训练验证已跑（`results/raw/pretrained_exact_mode_qwen_L*.json`）。
2. **τ=1e-5 下的真实任务精度未测**（PPL / MMLU）——决定方案可不可用
   的关键实验。
3. **深层泄漏的语料局限**——75% 的数字不能直接引用；可引用的是稀有
   token 49.4% vs 基线 8.7%。
4. Llama3 rope_scaling 未实现——不影响 exact 门禁（两条路径用同一个
   RoPE），但影响与 HF 参考的一致性，MMLU 长提示会被击穿。

## 7. 分析时的常见误区（FAQ）

**Q1：加大噪声（‖e‖）能不能让 h 恢复变难？**
不能。`c = [h,e]M` 是实数可逆变换，h 是**无损**编码在 c 里的。实测噪声
放大 10¹² 倍，恢复误差仍只有 5.7e-04（残差来自浮点精度，不是噪声遮蔽）。
机密性全压在"M 保密"上，不在噪声上。（§1.5）

**Q2：把 M 换成有损投影行不行？**
§1.7 的 `e ≈ hC` 通道仍然成立——辅助噪声 98% 是 h 的线性像，只要 C 可估，
泄漏就在。而且有损投影会破坏线性层的协变恒等式，等于换数学核心。

**Q3：ρ 攻击是不是只对第 0 层有效？**
第 0 层的 92–93% 是最严重、也最干净的结果（直接用公开 embedding 表，
与语料无关）。更深层的一对一"范数→token"关系不成立，但范数通道在所有
深度都携带真实 token 信息（稀有 token 49.4% vs 基线 8.7%，全 28 层不衰减）。
输入恰恰是要隐藏的东西，而第 0 层就是输入。

**Q4：测试全绿（303 passed）是不是说明没问题？**
不是。测试验证的是**数学正确性**（协变恒等式成立），不是**隐私目标达成**。
这两件事分离正是本次分析的核心教训：§3.1 的 PROBLEMS.md 把问题分成
"数学核心 ✅ / 工程实现 ✅ / 隐私目标 ❌"三层，问题只出在第三层。
另外 PROBLEMS.md §3.1 记录了一个教训：一个抓不到注入泄漏的守卫测试
曾给出"2 passed"的虚假保证——测试通过不等于测试有效。

**Q5：上游（Aloepri）能跑通就说明他们解决了？**
他们当前主路径 argmax 匹配 0/4、任务 smoke 12.5% vs 明文 87.5%，
正确性本身还没闭环（§4.1）。且其构造同样是"协变 + 非线性检查点"家族，
RMS 归一化因子仍是范数的函数（§4.2），同样的攻击面原则上适用。

## 8. 下一步建议（按优先级）

1. **补测 τ=1e-5 的真实任务精度**（PPL / MMLU，Qwen2-1.5B 本机可跑）。
   这是决定"折衷方案是否可用"的唯一关键实验，也是当前最大的证据缺口。
2. **评估路线 3（范数均衡 embedding）**：只解决第 0 层，但第 0 层正是
   输入所在、攻击最便宜的地方；若与首层权重联合转换，可能以零精度代价

4. 若第 1 步显示 τ=1e-5 任务精度不可接受，则需要认真讨论**放弃 C1–C4
   中的哪一条**（PROBLEMS.md §5 的不可能三角），而不是继续在现有构造内
   找工程补丁。
