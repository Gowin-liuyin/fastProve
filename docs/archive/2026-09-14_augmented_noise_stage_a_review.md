## A1：FP32 门禁字段使用了 FP64 闭环误差

`scripts/run_augmented_noise_kernel.py` 的 `run_closed_loop` 将输入基、输出基、h、W、b 和实际线性运算均设为 FP64。随后直接以该路径的 `signal_max_abs_error` 填写 `fp32_signal_gate_pass`，而环境记录写死 `activation_dtype=float32`。

raw 的信号最大绝对误差范围为 1.0214e-14 至 1.7764e-14，反映的是 FP64 参考闭环，不能作为每个配置的 FP32 部署结果。独立的 FP32 小测试确实存在且通过，但它使用较小的 d=8、r=2 和 fixed_refresh，不能替代 runner 全部配置的 per-record FP32 证据。

修复要求：分别执行 FP64 reference 与 FP32 deployment 两条路径，记录每个关键张量 dtype；每个配置用真实 FP32 误差判定 ≤1e-5 门禁。保留 FP64 参考误差供对照，不能只改字段名后继续声称 FP32 已验证。

`condition_number_fp32_stored` 目前取 `basis_fp32.condition_number`；生成器的这个值计算于 cast 前。应改为对实际存储的 FP32 矩阵转 FP64 后求条件数。已有 `inverse_residual_fp32_stored` 用 cast 后矩阵在 FP64 中测残差，属于存储误差检查，应与 FP32 乘法残差区分。

## A2：β 的标定单位偏离方案，且比例混用了检查点

方案定义 H=√E||h||²，σ_e=βH/√r。runner 实际传入：

```python
calibration_rms = h.norm(dim=-1).mean() / sqrt(signal_dim)
```

这近似是每坐标尺度，不是向量能量尺度。对当前 d=64 的合成信号，噪声范数比例因此约为 β/√64=β/8，与 raw 中 0.127 的量级一致。这不是「β=1 且特别稳定」，而是实际噪声比计划约小八倍。

修复要求：用独立校准样本计算 `H = sqrt(mean(sum(h_cal**2, dim=-1)))`，明确参数名/文档单位，将它传入 σ_e 公式。不要直接从攻击目标批次计算本应固定公开的尺度。记录 H、σ_e、校准样本来源和校准/目标 seed 的分离。

当前 `observed_noise_ratios(h, decoded_noise)` 用输入 h 除输出 e'；在线性输出维度已经从 64 变成 32 时，这不是同检查点的比例。应分别记录 ||e_0||/||h_0|| 与 ||e_1||/||h_1||，另列 RMS 能量比 √(E||e||²/E||h||²) 对照 β 定义。β 不要求每个 token 的范数比都等于它。

「30」来自既有 Gram 数值预算，不能作为新双侧基所有 dtype/维度下普遍安全的阈值。先记录实际误差，不能仅凭范数比小就推断数值稳定。

## A3：逐记录域分离尚未用于闭环，prefill/decode 检查只是种子重放

`record_generator` 提供了所需域标签，但 runner 的实际 e_0 和 ξ 由 `seed+3`、`seed+4` 的整批发生器生成，未按 sample_id/position 接入。改变 batch 顺序或分块大小时，同一逻辑记录未必取得相同噪声。

现有 prefill/decode 检查对同一参数调用相同采样函数两次，只证明确定性。应在实际闭环上比较整段、逐 token、分块、batch 重排后按 ID 对齐的采样结果及合法输出；不同层、用途、head、request/epoch 分别测试。

`test_record_generator_isolates_records_and_keeps_positions_stable` 在比较不同域时反复推进 base 发生器。即使某个域被错误忽略，也可能因读取到了同流的不同片段而通过。比较各域时应从新发生器读取相同偏移的首段。

runner 只有 `--output-dir`，没有加载新 YAML；13 条记录来自代码硬编码循环。修改 YAML 的噪声点、矩阵族、维度或设备不会改变运行。

## 指标和契约的解释修正

`noise_coverage_metrics` 使用 p_i=s_i²/Σs_j²、exp(−Σp_i log p_i)，对应 M_nᵀM_n 的非零协方差谱有效秩。应明确这个定义，不能直接称矩阵代数秩。字段 `row_norm_min/max` 实际计算列范数，应更名或加明确别名以免后处理误读。

β=0 时这些指标仍描述潜在注入映射 M_n；实际随机扰动为零，不能据此说零噪声配置也具有满覆盖。κ=1 有效秩接近 r 但仍保留正交结构，说明有效秩不能独立充当安全评分。

当前 COA 契约是字符串清单，不是实际攻击数据隔离器：`extra` 可携带任意值，尚无导出 tensor/文件的类型校验、参数归属审计或独立攻击进程。云端实际持有 Gram 时，应显式列为输入，不能依赖含糊字段遗漏。实际普通输出不应与被禁止的内部干净张量混用一个泛化 `plain_outputs` 标签。

这些属于进入 C 阶段前需要完成的接口，不据此声称已有测试错误地运行了攻击；本阶段确实尚无 COA 实验。

## 修复后的首批 B/C

先固定 d=64、r=16、κ=3、相同基础权重/数据/噪声能量。比较单侧与双侧、β∈{0,0.1,1,3}、3 个独立密钥，即每种观察范围 24 个配置。观察预算先 100 和 1,000，若值得继续再到 10,000。κ=1、κ=10 和 r=8 随后作结构压力测试，不先堆成全参数网格。

公平对照同时记录转换前 E||e||²/E||h||² 和转换后 E||eM_n||²/E||hM_s||²；不同矩阵可能改变可见空间的信噪比例。若观察到改善，要检查是否仅由可见噪声幅度不同造成，再做匹配可见噪声能量的补充对照。

transcript 先做频率/重复模式、范数距离指纹、无标签子空间估计；cloud 先检验实际可见噪声注入映射的零空间投影、Gram 恢复和公开权重对齐。后者不需要目标明文配对，但必须从真实云端包提取可见量，不能让评分方提供秘密推导矩阵。

先做简单攻击排除明显泄漏，再投入学习型攻击。合成连续 h 的实验可以测试几何/子空间恢复，却不能直接产生有意义的 token 恢复率；token 攻击需公开真实 embedding 或有明确 token 字典的离散小数据。目标 token 标签只交评分程序。

进入 B/C 的最低条件：A1–A4 修正后有新的 raw；正确 β 下的 FP32 门禁通过；实际闭环的分块/重排复现通过；攻击视图导出实际文件且不含目标秘密和标签。到时才能判定双侧基在固定攻击预算下是否优于单侧基。
